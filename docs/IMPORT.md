# Импорт портфеля v0.5

Парсер не привязан к интерфейсу. Он сначала строит кандидатов, ошибки и возможные повторы; сохранение делает PortfolioStore после проверки всего журнала. Загрузка файла не меняет портфель.

## Таблица операций

CSV: UTF-8, UTF-8 BOM или Windows-1251; разделитель запятая, точка с запятой или табуляция определяется по содержимому. XLSX: выбор листа и номера строки заголовков. Поддерживаются обычные строки/числа, inline/shared strings и Excel-даты 1900/1904 с датированным форматом ячейки. Формулы в используемых колонках и ошибки ячеек не вычисляются и блокируют импорт: нужны проверенные значения. PDF и старый бинарный XLS не поддерживаются. Лимит 10 МБ файла, 40 МБ распакованного XLSX, 5000 операций, 100 колонок; макросы не запускаются.

| Поле | Содержание |
|---|---|
| date | Обязательно: YYYY-MM-DD или DD.MM.YYYY, либо Excel-дата с форматом даты |
| kind | Обязательно: deposit / withdrawal / buy / sell / dividend / coupon или поддержанное русское название |
| symbol | Для сделок/выплат: тикер; ISIN или точное название можно разрешить через MOEX |
| quantity | Для buy/sell: целое количество бумаг, не лотов |
| price | Для buy/sell: рубли за бумагу; у облигаций полная цена с НКД |
| amount | Для денежных потоков и выплат: положительная сумма в рублях |
| fee | Неотрицательная комиссия в рублях, по умолчанию 0 |
| currency | RUB / SUR / RUR / ₽; если колонки нет, пользователь подтверждает рубли |
| source | Документ-источник выплаты; иначе имя файла |
| external_id | Номер операции/сделки; сохраняется строкой, включая ведущие нули |

Русские заголовки распознаются, но сопоставление можно исправить. Когда одному полю соответствуют несколько колонок (например, тикер и ISIN), автоматический выбор не делается. Одна колонка не может подставляться одновременно в разные поля. Неизвестный тип операции, отрицательная сумма, дробное количество, нераспознанная дата, неверное число или неизвестная валюта блокируют сохранение всего файла. Ошибочные строки не удаляются молча.

Идентификаторы проверяются в MOEX ограниченным запросом: прямой код, ISIN, точное совпадение названия. Первый нечёткий результат не выбирается. При отсутствии сети проверка явно помечена; синтаксически допустимый тикер можно сохранить только после самостоятельной проверки и подтверждения импорта. Названия на кириллице, которые не удалось преобразовать в код, не проходят валидацию журнала.

Даты сортируются стабильно: в пределах одной даты сохраняется порядок строк. Внутридневная дата/время не угадывается. При недостатке денег импорт не сохраняется; нужно добавить реальные входящие остатки/пополнения, а не выдуманное пополнение для обхода проверки. Если отчёт содержит отдельные таблицы денежных потоков и сделок, требуется привести их к единой таблице с корректной последовательностью. Произвольные многосекционные отчёты автоматически не склеиваются.

Пример `examples/portfolio_import_example.csv` — учебные суммы и цены, не реальные котировки и не выгрузка личного счёта.

## Предпросмотр и повторы

1. Выберите лист, строку заголовков, режим и сопоставление.
2. Нажмите «Подготовить предпросмотр». До этого ничего не сохраняется.
3. Проверьте все строки и сопоставленные бумаги. Исключите ненужные строки и отдельно проверьте возможные повторы.
4. Сверьте рассчитанный денежный остаток, позиции, комиссии, валюты и единицы цены с отчётом.
5. Подтвердите проверку и нажмите «Сохранить импорт». Весь пакет записывается атомарно.

Надёжный ключ — счёт + вид + дата + внешний номер. Без номера используется SHA-256 исходного файла и номер строки: повторная загрузка того же файла не удвоит операции. Экономически одинаковые строки из другого файла или внутри одного файла считаются *возможными* повторами: их можно исключить либо явно подтвердить как разные реальные операции. Они не удаляются автоматически. Идентификаторы импортированных строк сохраняются даже после исправления/удаления, чтобы старый файл не вернул ошибку. Смена сопоставления не является способом повторно импортировать прежнюю строку — используйте исправление записи.

Смена файла/сопоставления требует нового предпросмотра. Если журнал изменён в другом окне, старый предпросмотр не сохраняется до повторной проверки.

## Текущие позиции и JSON

В режиме позиций нужны symbol / quantity / price (средняя учётная цена). Дата и свободные деньги задаются явно. Получается один начальный остаток только для пустого журнала, без вымышленных сделок. Не суммируйте начальные остатки с уже импортированными покупками тех же активов. P&L всей истории остаётся неизвестным; сравнение стоимости открытых позиций с введённой себестоимостью показывается отдельно. Для доходности после переноса нужна реальная история оценок, первый день задаёт рыночную базу.

JSON — наш экспорт полного массива событий. Восстановление разрешено только в пустой журнал; это не универсальный формат отчёта брокера и не объединение двух портфелей. Операции повторно валидируются и проверяются полным воспроизведением.

## Что требует реального отчёта Альфы

Точные имена/структура таблиц, денежные остатки по секциям, сторнирования, отдельные комиссии, валюта/единицы облигационных цен, налоги и корпоративные действия. Образец не предоставлен; совместимость с полной нативной выгрузкой Альфы не заявлена. Можно предоставить обезличенный файл с заголовками и несколькими строками для отдельной проверки адаптера. Официальной синхронизации пока нет.
