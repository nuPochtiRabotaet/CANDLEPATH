# Decision Engine rules-0.4.0

`decision.decide(risk, profile_complete)` получает уже вычисленные факторы. Решение не основано на среднем прогнозном доходе, тексте LLM или случайном числе.

## Приоритет правил

1. Нет полного профиля → **Недостаточно данных**, личное соответствие невозможно оценить.
2. Есть хотя бы один hard_conflict → **Скорее не подходит**. Даже при пробелах данных уже наблюдаемый конфликт сохраняется; все пробелы показываются отдельно.
3. Есть critical_gap → **Недостаточно данных**, балл отсутствует.
4. Есть uncertainty → **Лучше дополнительно изучить**, частичное соответствие, без утверждения об инвестиционной привлекательности.
5. Иначе → **Скорее стоит рассмотреть**, соответствует только проверенным ограничениям, а не «дёшево» или «вырастет».

Текущий Risk Engine всегда отмечает отсутствие фундаментальной оценки/проверки состава фонда. Поэтому последняя категория в сквозном Advisor v0.4 **не достигается**: она предусмотрена контрактом для будущего расширения с проверенными данными. Отключателя этой проверки в UI нет. Это намеренное ограничение, а не обещание положительного сигнала.

При конфликте основной причиной становится первый конфликт в порядке вычисления (рынок, срок, предпочтение, концентрация, ликвидность, издержки, лот). Все решающие факторы возвращаются отдельно; отсутствие позитивного фактора не заменяется выдуманным преимуществом.

## Внутренний балл

Только при полном профиле и отсутствии critical_gaps: 100 минус фиксированные вычеты по уникальным id из hard_conflicts и uncertainties.

| id | Вычет |
|---|---:|
| drawdown | 40 |
| horizon | 25 |
| concentration | 25 |
| liquidity | 20 |
| costs | 10 |
| preference | 15 |
| model_disagreement | 10 |
| fundamentals | 10 |
| portfolio_unknown | 10 |
| history_warning | 10 |

Нижняя граница 0; при любом обязательном конфликте верхняя граница **40**, в том числе при конфликте lot, для которого отдельного вычета нет. Один id не списывается дважды. Балл не определяет категорию: приоритет правил важнее него. Это объяснимая учётная шкала, **не калиброванная вероятность, не прогноз доходности, не оценка качества бизнеса**. Суммарные вычеты могут учитывать связанные факторы; это одна из причин не интерпретировать шкалу статистически.

Выход содержит category/label/fit, main_reason, decisive_factors, deductions, rules_version, порядок правил и список того, что может изменить вывод. Методика воспроизводима для одних входов/версий. Время формирования отчёта не участвует в категории; дата проверки возраста данных участвует и сохраняется в parameters.as_of.

Пример: SBER, 5000 ₽, 12 месяцев, допустимое снижение 5%. Если наблюдаемая/модельная оценка риска выше 5%, результат unsuitable независимо от медианного дохода. Разница между этим выводом и «следует продать имеющиеся акции» принципиальна: движок проверяет указанные условия новой гипотезы и не отправляет поручений.
