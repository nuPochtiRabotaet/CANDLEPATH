**Итог проверки кода:** 408 Python-тестов, JavaScript syntax, Python compilation и синтетический Chromium smoke успешно прошли в **чистом GitHub Actions**: [Run #41072216320](https://github.com/nuPochtiRabotaet/FUCKBINANCEANDMOEX/actions/runs/41072216320).

## Протокол десяти проходов

| Проход | Проверка | Находка и действие | Итог |
|---|---|---|---|
| 1 | Подлинность текущей ветки и исходный тестовый запуск | Сверены `main`, активные PR, исходники движка; локальная среда не имела Streamlit/MCP | Выявлены ограниченные локальные тесты |
| 2 | Экстремальная ошибка прогноза | Воспроизведён `inf` в процентной ошибке, из-за чего JSON-экспорт падал | Decimal-аккумуляция; непредставимая ошибка теперь `null` с `unbounded_percentage_errors` |
| 3 | Гигантские числовые значения | `10**400` в цене/времени приводило к `OverflowError` | Live-движок возвращает `UNAVAILABLE`, replay — контролируемый `ValueError` |
| 4 | Чистая математическая модель | Входы `ewma_price_envelope()` с непредставимыми целыми могли вызывать исключение | Явное преобразование и проверка конечных положительных цен |
| 5 | Целостность OHLCV | Исторический replay проверял почти только close, мог принять свечу с high ниже close или NaN volume | Добавлена проверка `open/high/low/close/volume`, согласованности и полноты |
| 6 | Временные границы | Данные с будущей свечой, отмеченной как закрытая, могли войти в replay | Такие записи отклоняются до оценки качества |
| 7 | Отсутствие look-ahead | Прогнозный origin использует только предыдущие закрытые свечи; прогноз сравнивается с последующим фактом | Повторно прошли исходные replay/causality-тесты |
| 8 | Безопасность истории | Отдельный CLI исторической проверки не должен записывать «задним числом» live-прогнозы или менять SQLite | Повторно пройдено; публикаций нет, БД не изменяется |
| 9 | Рыночные параметры и UI | BTC/ETH/SOL и несколько таймфреймов; Chromium-тест отрисовки/отключения/восстановления | Профильные тесты и синтетический браузерный сценарий прошли |
| 10 | Полная независимая регрессия | GitHub Actions ранее падал **до создания jobs** из-за использования `runner.temp` в job-level env | Исправлена конфигурация, реальный job создан и завершён успешно |

## Что ещё не проверено и не означает «идеал»

1. Реальная история BTC/ETH/SOL из Bybit: полнота данных, стабильность REST/WS, отключение/восстановление сети, часовые пояса.
2. Физический Mac и Safari: интерфейс графика, производительность, сон/пробуждение.
3. Точная эмпирическая калибровка номинального 80%-диапазона на независимых данных и walk-forward без подбора на тесте.
4. Выгодные торговые BUY/SELL-сигналы с учётом комиссий и проскальзывания — **пока не реализованы/не доказаны**.
5. Приёмка последовательной цепочки зависимых PR до `main`; никакого автоматического merge и включения Live.

**Model state:** Random Walk median + EWMA, только `EXPERIMENTAL`. Исторический replay ≠ опубликованный тогда live-прогноз. Бесконечные/непредставимые численные ошибки не должны превращаться в ложные показатели качества. Никакие реальные сделки не включены.
