# Архитектура v0.7

Данные: прежние moex.py / data.py / portfolio_service.py / lab_data.py. Рыночная котировка — LAST либо явно датированный CLOSE; не PREVPRICE. Нет биржевой или брокерской торговой интеграции.

Финансовые модули portfolio.py, laboratory.py, advisor.py, decision.py, risk.py, backtest.py и time_machine_core сохранены побайтно. Sandbox.calculate вызывает прежний preview_trade на копиях событий. Ни sandbox.py, ни JS не вызывают PortfolioStore append/update/delete.

Представление: workbench.py содержит четыре основных маршрута. experience.py даёт общую карточку, форматирование, обзор и честное состояние истории оценок. portfolio_ui.py сохраняет журнал и импорт. lab_ui.py загружает источник и обрабатывает ручной fallback, цель и старые исследования.

interactive_lab.py монтирует официальный Streamlit components v2 с ключом, зависящим от актива, цен и ревизии портфеля. HTML/CSS/JS лежат в components/. Plotly берётся из установленного Python-пакета; CDN и Node-сборки нет. Во входной HTML/JS не интерполируются названия бумаг и пользовательские строки: данные передаются отдельно и вставляются через textContent.

Быстрый цикл: JS меняет локальное независимое состояние, обновляет суммы и графики, затем передаёт проверяемое состояние после debounce. Python validates/replays и возвращает авторитетный результат. Номер последовательности не позволяет старому подтверждению затереть новый ввод. При смене контекста создаётся новый ключ компонента. Журнал, изменённый другим окном, требует обновления снимка.

Тяжёлый цикл: раскрытие модели вызывает cached_history (TTL 900, max16) и cached_envelope (max16). Изменения количества, шока и поддержанного горизонта переиспользуют одну подготовленную модель. Котировки отдельные (TTL60, max32); портфельные marks — TTL60; старый снимок не получает новую дату рынка при чтении. Цель использует прежний capital_goal и отдельный fragment без рыночных запросов.

Сохранение: прежние SQLite и ResearchStore. Backup before-v0.7 выполняется до открытия существующих данных. Сценарий хранится в session_state; только явные кнопки сохраняют тариф или исследовательский снимок. Формат lab_scenarios совместим с v0.6. Исторические исследования не пересчитываются автоматически.

Для будущих методов: переиспользовать существующий контракт снимка с kind, instrument, parameters, method_version, computed_at_utc, data provenance, model/envelope, limits. Новые модели добавлять адаптерами; не создавать новый главный маршрут для каждого алгоритма.

Первичные справочники: https://docs.streamlit.io/develop/api-reference/custom-components и https://docs.streamlit.io/develop/concepts/custom-components/components-v2/register . API проверен также по установленному Streamlit 1.66.1.
