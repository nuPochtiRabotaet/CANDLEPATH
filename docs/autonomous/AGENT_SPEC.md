# Контракт автономного агента

Один агент обслуживает две задачи: выбирает проверяемые вопросы для Lab и предлагает решения на основании активного реестра. Планировщик задаёт лимиты стоимости, частоты запросов, времени выполнения и числа открытых исследований. При исчерпании бюджета сохраняется контрольная точка; управление защитой открытых позиций продолжает детерминированный runtime.

| Инструмент | Разрешённая операция | Проверка инструментального шлюза |
|---|---|---|
| market_snapshot / source_search / read_evidence | Читать данные на cutoff, искать разрешённые RSS/API/сайты и Telegram-каналы | Allowlist источника и операции, лицензия, лимит, доступность до cutoff, источник каждого поля. Секрет источника доступен только коннектору. |
| registry_lookup / risk_snapshot | Читать версии стратегий, режим допуска и обезличенные эксплуатационные ограничения | Результат версионируется. Risk пересчитывает состояние при принятии решения. |
| submit_research / read_result | Создать ограниченную офлайн-задачу с предрегистрацией, прочитать сохранённый результат | Sandbox с read-only development-срезом; запрет доступа к sealed данным, кошелькам и секретам. |
| append_memory | Добавить наблюдение, гипотезу, результат или разбор ошибки | Привязка к источникам, as-of, автору и версии; запись не меняет системные инструкции. |
| propose_intent | Предложить NO_TRADE, ENTER_LONG, REDUCE_LONG либо EXIT_LONG | Закрытая схема, допустимые версии, единицы, TTL и ссылки; идемпотентный приём, журнал отказов. |

Агент ранжирует вопросы по проверяемости, стоимости получения данных, новизне относительно журнала попыток и возможному эффекту после издержек. Фиксирует ожидаемый механизм, альтернативное объяснение и наблюдение, которое опровергнет гипотезу. В начале следующего цикла читает результат или причину остановки своего предыдущего задания. Модель может предложить новую версию стратегии только в EXPERIMENTAL.

## Формат решения

Ниже иллюстрация отказа с синтетическими идентификаторами. Схему формализовать и протестировать до подключения инструментов.

```json
{
  "schema_version": 1,
  "intent_id": "example-41",
  "mode": "PAPER",
  "action": "NO_TRADE",
  "instrument": "BTCUSDT",
  "strategy_ref": {"id": "example", "version": "1"},
  "mandate_revision": 3,
  "data_cutoff": "2026-11-23T10:00:00Z",
  "decided_at": "2026-11-23T10:00:03Z",
  "expires_at": "2026-11-23T10:00:10Z",
  "source_refs": ["example-observation-1"],
  "market_snapshot_id": "example-snapshot",
  "model_version": "example-model@revision",
  "policy_version": "example-prompt@revision",
  "cost_model_ref": "example-cost@1",
  "quantity_base": null,
  "exit_plan": null,
  "reason_codes": ["STALE_QUOTE"],
  "rationale": "Нельзя оценить цену доступного исполнения.",
  "uncertainty": {"missing": ["fresh_bid_ask"]}
}
```

Для входа обязательны версия APPROVED с правильной средой, доступные доказательства, сторона Spot, предложенное количество в base как десятичная строка, предельный расход в quote, срок решения, stop/target либо иной заранее зарегистрированный выход и максимальный горизонт. Для сокращения/выхода нужны ссылка на позицию и предел продаваемого остатка. Для NO_TRADE допустим пустой план; запрет может быть глобальным при недоступном реестре. Агенту нельзя создавать поля результата Risk или исполнения.

Decision Engine дополняет запись: собственное время приёма и проверки, фактический рыночный режим, digest входов и правил, версии реестра/мандата/модели, расчёт издержек и основания одобрения или отказа. Risk присоединяет независимый вердикт, binding limit, разрешённое количество, срок и резерв. Исполнитель присоединяет фактические ACK/fill/fees через отдельные события. Хранить воспроизводимый запрос к модели, версию и фактически полученный структурированный ответ с политикой редактирования секретов; повторный вызов LLM может дать другой текст. Детерминированное воспроизведение начинается с сохранённого намерения.

## Недоверенный контент и память

Присваивать каждой публикации digest, origin, язык, источник, права на хранение, timestamps и уровень доверия. Ссылка на копию того же сообщения не повышает число независимых подтверждений. HTML/сообщения приводить к ограниченному полю данных; вложенные инструкции, ссылки и предложения вызвать инструмент не меняют allowlist. Для спорных событий сохранять конкурирующие версии и основание оценки. Непроверенное событие может породить только исследование.

Разделять эпизодические наблюдения, карточки гипотез, формальные отчёты и утверждённые человеком правила. Поиск памяти уважает time cutoff и среду. Отзыв/исправление помечает старую запись и источники производных решений; опубликованное решение остаётся в журнале. При разборе ошибки сравнить прогноз с исходом, план с фактическим исполнением и причины расхождения. Секреты и произвольный executable-код в память не попадают.

Таймаут, неверная схема, конфликт повторного intent_id, недоступность инструмента, неизвестная версия или просроченные данные дают зарегистрированный отказ. Повтор чтения ограничен backoff/TTL; повтор намерения возвращает первоначальный результат для того же digest. Модель не меняет роли, мандат, реестр APPROVED, риск-политику, SQL ledger, конфигурацию endpoints и состояние kill switch. [Граница исполнения](ARCHITECTURE.md)
