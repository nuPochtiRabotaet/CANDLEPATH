# Backlog для двух разработчиков

Состояние при создании плана: BASE-01 готова к назначению. Остальные задачи запланированы и открываются по указанным зависимостям и воротам этапа. Исполнителя назначать в одном Issue или PR на ID. P0 обозначает блокирующий безопасность или доказательность результат, P1 — следующий необходимый инкремент, P2 — улучшение наблюдаемости/удобства. Приоритет не разрешает перескакивать через этап.

| ID | Приоритет / этап | Зависит от | Изменение и проверяемая приёмка |
|---|---|---|---|
| BASE-01 | P0 / 0 | Сверенный develop | Добавить один регрессионный тест аварийного завершения владельца Paper. На временной SQLite с подтверждённой тестовой записью второй процесс получает отказ, пока первый жив. После принудительного завершения новый владелец приобретает lock, cash, позиции и IDs прежних проводок сверены, повторной проводки нет. Ноль сетевых отправок. |
| BASE-02 | P0 / 0 | BASE-01 | Сверить матрицу веток/CI и миграцию учебной схемы 4→5. Проверить backup, восстановление, более новую схему, cash/base/dust и отсутствие затрагивания Invest; зафиксировать исключённые платформы и решения по конфликтующим PR. |
| RUN-01 | P0 / 1 | BASE-02 | Выделить headless Local Paper entry point. Открытие и закрытие браузера не запускают второго worker, статус и защита читаются отдельным клиентом. |
| RUN-02 | P0 / 1 | RUN-01 | Ввести устойчивые к повторам команды halt/status/recover, durable outbox для локального контура. При падении перед/после записи команда оставляет один эффект, старые намерения не отправляются. |
| SRC-01 | P1 / 2 | RUN-02 | Реестр источников, as-of события и карантин. На наборе поздних, переставленных и повторных сообщений префиксы идентичны; пропуск виден в статусе. |
| SRC-02 | P1 / 2 | SRC-01 | Подключить один официальный новостной источник с подтверждёнными правами, затем разрешённый Telegram при наличии доступа. Сохраняются ссылка, времена и происхождение; перепечатки объединяются, версия исправления доступна по cutoff. |
| AGT-01 | P1 / 3 | SRC-02 | Один изолированный агент с read tools, квотами и append-only памятью. На тестах внедрённых инструкций не появляется новых инструментов, сетевых адресов или финансовых записей. |
| DEC-01 | P0 / 3 | AGT-01 | Валидатор Intent и DecisionRecord в shadow. На просроченной версии, неизвестной стратегии или пустом реестре сохраняется NO TRADE. Решение воспроизводится по сохранённому ответу и снимку. |
| LAB-01 | P0 / 4 | DEC-01 | Протокол и runner с provenance, purged folds и блокировкой holdout. Повтор на фиксированной версии численно воспроизводим; отчёт показывает потери, costs, baseline и поправку на предыдущие попытки. |
| REG-01 | P0 / 4 | LAB-01 | Подписанные переходы версий по ролям, сроку и scope. Тесты отвергают self-promotion, перенос Demo-допуска в Live и покупку после SUSPENDED. |
| RSK-01 | P0 / 4 | REG-01, RUN-02 | Одноразовый допуск и транзакционный резерв, привязанные к ревизии мандата. Два конкурентных намерения в сумме не превышают ни cash, ни лимит; истечение, отзыв и неопределённая отправка учтены. |
| EXE-01 | P0 / 5 | RSK-01 | Persistent FSM и reconciliation на изолированной фикстуре, затем официальном Demo. Повтор, partial, cancel race и lost ACK не создают второго fill; до сверки сохраняется резерв. |
| EXE-02 | P0 / 5 | EXE-01 | На официальном Demo сверить фактические fee, dust, доступный баланс и защиту после частичного исполнения и рестарта. К журналу приложить очищенные от секретов свидетельства. |
| OPS-01 | P0 / 6 | EXE-02 | Приёмка сервиса на сервере по утверждённым SLO, восстановление backup, ротация секрета, оповещение вне UI, проверка stop при открытой позиции. Опубликовать отчёт учений. |
| UI-01 | P1 / 6 | RUN-02, REG-01, EXE-02 | Панель владельца показывает версию полномочий, риск, заявки, исполнения, источник решения, доходность, просадку и отказ. Изменение капитала требует нового мандата, halt работает без вкладки UI. |
| UI-02 | P2 / 6 | UI-01 | Один путь от тревоги до источника новости, гипотезы, решения и статуса покрытия. Проверить доступность и понятность остановленных состояний с обоими разработчиками. |
| LVE-01 | P0 / 7 | OPS-01, UI-01, **независимые** экономический и security допуски | Собрать досье конкретного Live-релиза, запрет отправки до отдельного разрешения владельца проверить отрицательным тестом. Даже при готовом коде отсутствие одобренной стратегии оставляет Live выключенным. |

Не создавать все Issue автоматически. Следующая задача после BASE-01 выбирается на совместном review с учётом фактических результатов. [Приёмка этапов](ROADMAP.md) · [Порядок работы](CONTRIBUTING.md)
