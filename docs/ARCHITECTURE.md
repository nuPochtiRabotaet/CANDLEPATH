# Архитектура v0.4

Платформа расширяет v0.3, сохраняя Python/Streamlit и общий DataEngine. Внешняя LLM не участвует в численных расчётах.

| Слой | Файлы и контракт |
|---|---|
| MOEX ISS | `moex.py`: async запросы, таймауты, повторяемые сетевые ошибки, кеш и постраничная история |
| Данные | `data.py`: описание инструмента, основной режим, RUB/процент номинала/пункты индекса, нормализованный DataFrame и provenance |
| Quant | `time_machine_core/simulator.py`, `backtest.py`, `portfolio.py`: независимые детерминированные расчёты |
| Риск | `risk.py`: факторы, hard_conflicts, uncertainties, critical_gaps; неизвестное отдельно |
| Решение | `decision.py`: фиксированный приоритет правил, версия, объяснение и вычеты |
| Оркестрация | `advisor.py`: validate → data quality → lot sizing → two models → risks → decision → report |
| Сравнение | `comparison.py`: общие даты, ценовые метрики, beta и нормализованные ряды |
| Хранение | `persistence.py`: настройки и снимки исследования в SQLite; отдельный прежний PortfolioStore |
| Представление | `workbench.py`: 9 страниц; `dashboard.py`: сохранённые страницы/графики и совместимый вход |
| ИИ | `mcp_server.py`: 15 read-only инструментов, те же численные функции; `server.py` — прежние 5 |
| Жизненный цикл | `launcher.py`, три `.command`: локальный supervisor, health, выбор порта, остановка собственных процессов |

UI и MCP вызывают общие функции, их кеши существуют раздельно в процессах. `evaluate(frame, meta, quote, profile, portfolio, ...)` не обращается к сети; `investigate(...)` получает данные и выполняет evaluate в рабочем потоке. Режим Beginner/Advanced не передаётся в расчётные функции.

История исследования — JSON результата плюс CSV цен, параметры/seed/версии/профиль/котировка и SHA-256; при чтении проверяется digest. Повторное исследование создаёт новый UUID. Изменение старой записи через приложение не предусмотрено. Проверка хеша обнаруживает повреждение, но не является криптографической подписью или защитой от владельца локальной БД. Предпочтения ограничены разрешёнными полями, ключи API не используются. Портфель хранится отдельно и не читается MCP автоматически.

Конфигурация через `Settings.from_env()`, без секретов. UI и MCP привязаны к loopback, HTTP MCP проверяет Host/Origin. Ошибка рынка не приводит к скрытому демо. Демо имеет фиксированный ряд и явную маркировку. История заканчивается прошлой московской датой, метаданные содержат дату фактического наблюдения.

Независимые unit-тесты покрывают математику/правила/журнал, протокольные тесты — MCP stdio, AppTest — Streamlit, отдельные скрипты — live ISS, HTTP и реальный браузер. Архитектура не содержит брокерских приказов, eval пользовательского кода или веб-загрузки Python-стратегий. Пользовательская стратегия — доверенная локальная Python-функция через API, пример в `examples/custom_strategy.py`.

## Дополнение v0.5: функциональный портфель

`portfolio_ui.py → portfolio_service.py / portfolio_import.py → portfolio.py → SQLite`.

UI отвечает за выбор, формы и подтверждение сохранения. Импорт преобразует таблицы в валидируемые события и показывает ошибки, но сам не пишет в БД. Сервисы получают реальные котировки через прежний DataEngine, явно описывают источник/дату цены и собирают контекст Advisor. Ledger остаётся независимым от Streamlit. Визуальные стили прежние; полноценное выделение всех компонентов старого UI в дизайн-систему отложено вместе с редизайном.

Схема событий v0.4 сохранена, добавлены account_id, таблицы revision/audit/import_keys. Отдельное событие opening фиксирует исходные бумаги и деньги; оно не считается сделкой. Исправления выполняются UPDATE/DELETE существующего ID, без компенсирующих покупок/продаж. BEGIN IMMEDIATE + expected_revision + полный replay предотвращают частичную запись и устаревшие исправления. Таблица import_keys сохраняет след даже после удаления события. При старой схеме перед миграцией создаётся SQLite backup.

Расчёты после каждого действия получают актуальный bundle; кешируется только рыночная цена, а не NAV/структура. Полный NAV доступен только при оценке всех позиций. При отсутствии LAST допустим явно датированный реальный close, а не цена приобретения. Снимки исследований остаются неизменными; текущий Advisor при новом запуске может получить актуальный портфель.

MCP сохраняет 15 read-only инструментов. Личный SQLite не открывается внешнему ИИ автоматически; события и оценки передаются инструментам явно. Брокерских торговых вызовов нет.

## v0.6: инвестиционная лаборатория

Слой `lab_ui` содержит Streamlit/Plotly, `laboratory` — независимые расчёты, `lab_data` — загрузку и отдельный кеш публичных котировок. `portfolio_service.asset_market_data` — общий путь цены для портфеля и лаборатории: LAST либо явно датированное реальное закрытие, с подтверждёнными единицами/валютой и НКД. Бизнес-логика не зависит от визуального оформления.

`preview_trade` копирует события/оценки и использует прежние `ledger_state` / `analyze_portfolio`. Ни PortfolioStore, ни брокерские операции этим модулем не импортируются. Гипотетическое пополнение — внешний поток, комиссия — уменьшение NAV; положительный сдвиг из-за пополнения не называется прибылью. Неизвестные тариф/лот/номинал/НКД/валюта не заменяются фиктивными значениями. Отсутствие оценок других позиций блокирует общий NAV, но не известное количество/деньги/стоимость выбранной бумаги.

Ползунок ценового стресса использует `stress_test`; у облигации процент изменения чистой цены переводится в изменение полной рублёвой цены при фиксированном НКД. Этот сценарий хранится отдельно от статистического envelope. Статистический envelope вызывает неизменённый `simulate` с удержанием до горизонта; повторно используется при изменении количества и выбранного горизонта. Остальные активы фиксированы: это условная модель одной позиции, не совместная портфельная симуляция.

Streamlit fragments ограничивают перерисовку лёгкой лабораторией. Кеши цены (60 с), истории (900 с) и модельных квантилей имеют отдельные ключи; количества, комиссии и стресс не запускают загрузку истории. История загружается только при явном включении модели или переходе «Оценить / Сценарии». Снимок портфеля привязан к revision; изменение в другом окне требует обновления перед продолжением.

Сценарное исследование сохраняется в прежнем ResearchStore как `kind=lab_scenarios`, с исходными ценами и параметрами; старые Advisor-снимки читаются прежним путём. Новая настройка commission фильтруется до числовых полей. Перед первым открытием старых данных `upgrades.ensure_v06_backup` делает SQLite backup обеих существующих баз. Снимки рыночных цен сохраняются отдельно с SHA-256; их исходный timestamp никогда не обновляется вслед за чтением устаревшего кеша.

Документация библиотек: https://docs.streamlit.io/develop/api-reference/execution-flow/st.fragment , https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_data , https://docs.streamlit.io/develop/api-reference/charts/st.plotly_chart . Фактически использованы установленная Streamlit 1.66.1 и Plotly 6.9.0; зависимости v0.5 не изменялись.
