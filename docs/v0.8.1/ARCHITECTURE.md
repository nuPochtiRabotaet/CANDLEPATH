# v0.8.1 — граница проверенного этапа

Это промежуточная версия из последовательности v0.8.1 → v0.8.2 → v0.9. Выполнены критические исправления и жизненный цикл сигналов. Прогнозирование, оптимизация индикаторов, новая тарифная модель и Demo не включены в эту сборку.

## Аудит и сохранность

Рабочая копия создана из доступного дерева v0.8, стабильная папка не изменена. Повторный baseline из корня исходников: 219 тестов. Первый запуск из родительской папки дал один FileNotFoundError в проверке, использующей относительный путь; этот неуспешный запуск сохранён, затем команда исправлена без изменения теста. Число 221 из прежнего отчёта не переносится как результат текущего запуска.

Исходные точки входа app.py/dashboard/workbench, Streamlit v2, Plotly Invest, SQLite portfolio/research и локальный launcher сохранены. Изменены только crypto, его компонент и точка резервного копирования в workbench. Побайтовая проверка 15 модулей инвестиционного ядра — preservation.json. Новый MP4 просмотрен на кадре 3 секунды: свечи, зелёная/розовая лента и тонкие линии; алгоритм по видео не копируется.

Crypto schema v2 сохраняет прежние таблицы и добавляет protective, lifecycle, notifications. Перед миграцией schema v1 создаётся SQLite backup `<имя БД>.before-v081`; новая схема создаётся транзакционно. Portfolio/research отдельно копируются в backups/before-v0.8.1. Для отката сначала остановите приложение, сохраните новые данные и восстановите crypto backup; v0.8 не должен открывать schema v2. Новая база сохраняет имя crypto-v08.sqlite3 для автоматического продолжения истории.

## Защитное обязательство и попытка

Обязательство связано с position_id (новые позиции) или symbol/opened (старые). Каждая попытка имеет отдельный UUID. Таблица protective атомарно резервирует попытку с 30-секундной lease. Повтор незавершённой попытки после сбоя использует тот же UUID, поэтому уже записанное исполнение не повторяется. После Rejected следующая попытка получает новый ID.

Без изменения условий retry ограничен 30/60/120/240/300 секундами. Изменение шага, tick, minimum, maximum, валидности правил или допустимости notional допускает немедленную новую проверку. Обновление одного retrieved timestamp с теми же действующими ограничениями не вызывает постоянных повторов. Остаток и identity позиции проверяются внутри BEGIN IMMEDIATE; защитная заявка не может закрыть новую позицию, появившуюся после старой.

Частичная SELL, оставляющая notional ниже минимума или некратный остаток, отклоняется без изменения денег/позиции. UI предлагает отдельно подтверждаемое полное закрытие. Уже существующий dust не считается исполненным: можно ждать изменения условий либо явно списать **виртуальную** позицию в убыток без возврата денег. Written Off — отдельная учётная операция, не Filled и не биржевой SELL.

## Источники котировок

Bybit Spot Ticker snapshot не гарантирует bid/ask. Production подписывается на kline, tickers и orderbook.1; последний является snapshot-only согласно официальной документации. Стороны стакана имеют собственные timestamps; ticker не обновляет их возраст. Пустые/нулевые/нечисловые/инвертированные стороны блокируют исполнение. Устаревший пакет стакана/свечей не заменяет более новый. Для обратной совместимости публичный Bybit.stream по умолчанию оставляет две прежние подписки; Feed явно включает include_book=True.

Отдельно выводятся transport_connected, market_stream_active, last_price_fresh, bid_ask_valid, candle_data_fresh, rules_fresh, trade_execution_ready. Время last/bid/ask ≤15 секунд, расхождение timestamps ≤5 секунд. Статус соединения не разрешает сделку сам по себе: Python заново проверяет quote/rules/риск. Actionable требует также свежей свечи. Котировки REST не опрашиваются каждую секунду. Правила обновляются после часа, неудачные refresh ограничены минутой.

## Монитор защиты

PaperMonitor — daemon thread локального процесса Streamlit; реальных ордеров нет. После открытия Trade он сохраняется при закрытии страницы и переключении в Invest. Раз в 2 секунды читает сохранённые позиции, поддерживает независимую lease feed и проверяет защиту. Транзакционные попытки исключают двойное закрытие при одновременной проверке UI и worker.

Это **не установленный системный сервис macOS**. После остановки процесса/сна компьютера защита отсутствует. После перезапуска требуется открыть Trade. Heartbeat старше 8 секунд или неполные котировки показывают Protective Orders Not Actively Monitored. Повторные отказы и dust отдельно доступны в панели состояния. Active означает работу локального наблюдателя, не гарантированное исполнение. После offline-разрыва нет выдуманного ретроактивного исполнения по стопу: используется следующая допустимая наблюдаемая цена.

## Сигналы и уведомления

analysis.py остаётся эталоном причинного полного расчёта. provisional вызывает тот же набор условий на копии текущего состояния; оригинальные свечи и confirmed-журнал не изменяются. WATCHING: EMA21 выше EMA55, цена в пределах 0,5 ATR от EMA21; это приближение, не BUY. POTENTIAL: полный набор условий стратегии на незакрытой свече; исчезновение условий ведёт к INVALIDATED, повторное появление в той же свече сохраняет first_seen.

CONFIRMED фиксируется только после временной границы закрытия. confirmed_at/available_at — фактическое время обнаружения приложением, boundary timestamp хранится отдельно. Маркер условия находится на следующей временной границе свечи; tooltip явно показывает фактическое обнаружение и запрещает трактовать историю как исполненную сделку. Подтверждённое событие не переписывается, его актуальность меняется отдельно.

TTL: Trend/Breakout — один интервал после закрытия, Mean Reversion — два. Entry zone = reference −0,25 ATR … reference +0,5 ATR; invalidation = signal stop. Верхняя граница превышена → EXPIRED / Opportunity Missed; стоп или несовместимый режим → INVALIDATED. Нет свежих данных → остаётся CONFIRMED, Actionable запрещён. Риск выбранного количества не проходит → REJECTED_BY_RISK. При восстановлении риска до expiry состояние может стать ACTIONABLE. EXIT означает выход из имеющегося long, а не short. Исторические обнаружения старше 60 секунд после границы не получают Actionable и не создают лавину уведомлений.

Эти TTL/диапазоны — явно заданные проектные правила, не статистически оптимальные параметры. Вероятность прибыли не заявляется. Net R/R берётся из существующего калькулятора с издержками; предупреждение при R/R<1 не является запретом сделки. Полная конфигурируемая quality policy и Maker/Taker fees относятся к v0.8.2.

Notifications: максимум одна запись на (signal ID, state), first_seen сохраняется после рестарта. UI имеет звук по явному включению и browser notifications по разрешению. Отказ браузера не прерывает работу. Уведомления формируются при открытом Trade; закрытая вкладка не получает обещания доставки. Это отдельно от работающего в процессе монитора стопов.
