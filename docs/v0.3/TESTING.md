## Что именно проверяют тесты

**Данные:** исходные повторы, пагинация и остановка зацикливания, отсутствие подмены LAST, malformed JSON/tables, идентификаторы, невалидные диапазоны, настоящая схема description/boards, bond URL, отрицательные цены, дубликаты/пропуски/порядок дат, кеш TTL, сохранение времени загрузки, изоляция изменяемого ответа, отсутствие кеширования ошибок и сетевых подстановок.

**Математика:** постоянная цена и точная формула комиссии на входе/выходе; VaR/ES для известного распределения; гэп через стоп с выходом по CLOSE, а не по уровню; замораживание стоимости после выхода; детерминированный seed; сумма частот исходов; запрет NaN/Infinity, bool и недопустимых размеров; три сценарных предположения.

**Стратегии:** ручной пример покупки по следующему OPEN; целые лоты; точные комиссии на постоянной цене; изменение будущего не меняет прошлые сигналы MA/RSI/Buy & Hold; RSI на растущем, падающем и постоянном ряду; custom callable получает только исторические префиксы; одинаковые даты/капитал test и benchmark; пропуски OPEN не удаляются.

**Портфель:** cash, cost basis, частичная продажа, дивиденды, realized/unrealized P&L, стресс; запрет отрицательного cash, short и неизвестной валюты; источник выплаты; SQLite rollback при ошибке; пополнение не становится инвестиционной доходностью; устаревшие/отсутствующие оценки отклоняются.

**Интеграция:** обе формы MCP (stdio/HTTP), schema/structuredContent, отсутствие побочных торговых действий, loopback-only конфигурация, передача ошибок, сквозная работа всех разделов UI.

## Производительность

Отдельный прогон: 10 000 сценариев × 120 торговых дней, 1 210 000 ячеек. В тестовой Linux-среде вычисление заняло **0.0821 секунды**, максимальный RSS процесса — **184.13 MiB**. См. `performance.json`. Это измерение численного ядра, не времени скачивания данных/отрисовки и не бенчмарк MacBook. Для стандартных 10 000 × 20 нагрузка ниже. Предел произведения размеров и один вычислительный слот действуют на каждый процесс отдельно.

## Обнаруженные и исправленные ошибки интеграции

Первая серия дала 73 успешных и 2 неуспешных проверки: недостающая output schema у bridge и конфликт ключа кнопки со значением отчёта в Streamlit. Обе исправлены, финальный набор — 75/75. Браузерная проверка дополнительно ожидала фактическую отрисовку Plotly, а не только появления метрик, после чего изображения просмотрены визуально.

## Как повторить

Из корня проекта после установки `requirements-dev.txt`:

```bash
python -m pytest -q --junitxml=docs/test-results.xml
python -m scripts.verify_http
python -m scripts.verify_live
python -m scripts.verify_reader
python -m examples.custom_strategy
python -m examples.portfolio_analysis
```

`verify_live` и `verify_reader` требуют доступа к MOEX и перезаписывают соответствующие отчёты. Сетевое падение — ошибка проверки, не основание включить synthetic mode.

Браузерный тест — отдельная необязательная QA-зависимость:

```bash
python -m pip install playwright==1.51.0
python -m playwright install chromium --only-shell
python -m scripts.verify_browser
```

Он запускает временный Streamlit на loopback и использует отдельную временную базу: личный портфель не меняется. Browser runtime не нужен для обычного запуска приложения.

## Что не проверено / не заявляется

- Физический MacBook Apple Silicon, Safari и мобильные браузеры. Разрешение macOS ARM64 wheels прошло, но это не тест выполнения на Mac.
- Публичный MCP, OAuth, TLS-терминация, внешний ChatGPT/Claude-клиент и развёртывание в Docker. Локальный протокол проверен; облачное подключение не заявляется.
- Длительный многопользовательский нагрузочный прогон. Это однопользовательский локальный MVP.
- Корректность/полнота сведений самой MOEX, реальная исполнимость сделок, корпоративные действия и налоговый учёт.
- Калибровка модельных частот относительно будущего рынка, статистическая значимость доходности стратегии, прибыльность в торговле.
- Автоматическая верификация пользовательских дивидендов, купонов и ручных оценок.

Зелёные тесты подтверждают перечисленные контракты и сценарии, а не гарантированную доходность или отсутствие любых возможных ошибок.
