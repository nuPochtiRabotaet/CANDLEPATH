Python-окружение для baseline создано отдельно. Прямое обращение к MOEX подтвердило доступность API и фактическую схему `description` / `boards`.

## Решения по компонентам

| Компонент | Что сохраняется | Что исправлено / почему |
|---|---|---|
| Reader ISS | httpx, повторы временных ошибок, пагинация, валидация идентификатора, LAST без подмены | Поддержка bonds как отдельного рынка, дополнительные проверки строк/дат/цен и TransportError |
| Reader metrics | Формулы доходности, волатильности, просадки, SMA | Не принимает bool вместо цены; контракт сохранён |
| Пять MCP-инструментов | Имена, аргументы, структурированные ответы | Общий DataEngine; отдельная фабрика не мутирует legacy singleton |
| Bootstrap | Непрерывные блоки лог-доходностей, seed, первое дневное пересечение, издержки, прежние stats | Убрана скрытая чистка цен, добавлены ресурсные лимиты и риск-метрики |
| Time Machine loaders | Публичные функции и адаптер HistoryLoader | requests-дублирование заменено вызовом общего Reader |
| Bridge | `run_analysis`, `register_time_machine_tools`, два имени инструментов | Typed output schema и выполнение sync-кода в потоке внутри MCP |
| Streamlit | Стек, параметры симуляции, веер, распределение, CSV, demo | Единое приложение с шестью разделами и сохранением результатов расчёта в сессии |
| Docker / public tunnel | Исходные файлы остаются внутри архива | Не используются новым MVP: прежний путь публиковал сервер без авторизации |
| Backtest / Portfolio | В исходниках отсутствовали | Реализованы отдельными тестируемыми модулями |

## Найденные проблемы

1. **Неверная схема карточки инструмента.** Загрузчик Time Machine ожидал таблицу `securities` на `/securities/{ticker}`, тогда как реальный ответ использует `description`. Тест проверял упрощённый искусственный ответ и не обнаруживал ошибку.
2. **Молчаливое изменение истории.** `dropna`, фильтр положительных CLOSE и удаление дубликатов могли соединить соседними доходностями даты через пропуск. Теперь невалидная история отклоняется с датами проблемных строк. Старое ожидание теста «null удаляется» намеренно отменено.
3. **Bridge не был интеграцией по умолчанию.** При отсутствии адаптера он повторно скачивал данные своим requests-клиентом. Теперь все штатные пути проходят через DataEngine → ISS.
4. **Sync/async.** `asyncio.run` синхронного адаптера нельзя вызывать прямо в уже работающем event loop FastMCP. Реальная регистрация использует `background=True` и `asyncio.to_thread`.
5. **MCP output schema.** Возврат bare `dict` в bridge не обеспечивал требуемую структурированную схему. Исправлен на `dict[str, Any]`, проверен через настоящий протокол.
6. **Ресурсы.** Независимые пределы числа сценариев и горизонта разрешали слишком большие матрицы. Теперь ограничено их произведение и параллельное выполнение.
7. **Синтетическая история меняла даты каждый день.** Дата конца demo теперь фиксирована, валидна для повторяемых тестов. Synthetic-флаг учитывается и при передаче собственного loader.
8. **Сетевой доступ.** Старый Reader позволял HOST=0.0.0.0 и PUBLIC_HOST без аутентификации. Новая конфигурация отказывается запускаться вне loopback; это намеренное изменение безопасности, не потеря рыночных функций.
9. **Незафиксированные зависимости v0.1.** Диапазоны заменены согласованными lock-файлами с транзитивными версиями, маркерами платформ и хешами.
10. **История режима торгов.** У SBMX доступная история текущего primary board начиналась позже запрошенного периода. Добавлены фактические границы и предупреждение; разные режимы автоматически не склеиваются.

## Регрессии

Все 15 тестов оригинального Reader включены без изменений в `tests/legacy/test_reader.py`. Пять тестов симулятора и шесть тестов bridge также перенесены без изменения. Проверки исходного отдельного загрузчика заменены тестами общей схемы и строгой валидации; оригиналы доступны внутри архивов. Новый набор дополняет их ручными математическими примерами, проверками протокола, сети, кеша и интерфейса.
