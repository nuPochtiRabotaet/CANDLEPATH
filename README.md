# MOEX Intelligence v0.8.2-rc3

Рабочий промежуточный релиз, **не готов к реальным средствам**. Invest и Crypto сохранены.

## Поддерживаемые платформы

- Windows 10/11 (64-bit), Python 3.12 или 3.13.
- macOS (Intel и Apple Silicon), Python 3.12 или 3.13.

Для каждой операционной системы создаётся собственное виртуальное окружение `.venv`. Не копируйте `.venv` между компьютерами или ОС.

## Запуск на Windows

1. Установите Python 3.12 или 3.13 (64-bit) с [python.org](https://www.python.org/downloads/), включая Python Launcher.
2. Скачайте ZIP репозитория и распакуйте проект, например, в `C:\CANDLEPATH`.
3. Запустите `setup.bat` и дождитесь установки зависимостей.
4. Запустите `start.bat`. Откройте адрес, показанный в окне (обычно `http://127.0.0.1:8501`).
5. Для штатной остановки запустите `stop.bat`.

## Запуск на macOS

1. Сохраните резервную копию пользовательских данных (обычно `~/.moex-intelligence` или каталог `MOEX_DATA_DIR`). Не удаляйте историю.
2. Распакуйте проект. Нужен Python 3.12 или 3.13; на Mac M-series — arm64/universal2. Не переносите старую `.venv`.
3. В Terminal перейдите в папку проекта и выполните:

```bash
chmod u+x *.command
bash setup.command
bash start.command
```

Остановка — `bash stop.command`. Диагностика Bybit — `bash check_bybit.command`. Существующие macOS-скрипты сохранены; общий supervisor выбирает параметры запуска процессов для текущей ОС.

## Данные и обновление

Данные приложения локальны для каждого компьютера и сами по себе не синхронизируются через GitHub. Не помещайте базы данных, ключи API, `.env`, `.runtime` и виртуальное окружение в репозиторий. Перед обновлением сделайте резервную копию данных. Только Crypto SQLite мигрирует 4→5 с резервной копией `crypto-v08.sqlite3.before-rc3`; портфель MOEX не мигрирует. Для отката остановите процесс, сохраните новые данные отдельно и восстановите копию базы вместе со старой версией. rc2 не открывает schema 5.

## Что проверить первым

Trade → BTCUSDT → 15m → Paper Trading. Количество либо сумма 25 USDT → предпросмотр → явное подтверждение. Всё — локальные виртуальные средства. Сумма Notional допускает комиссию сверху, Total ограничивает списание. Ключ для публичного рынка не нужен.

В открытой позиции смотрите «На счёте / продаваемо / остаток». «Продать доступное» продаёт ровно разрешённое количество; дробный остаток и себестоимость сохраняются. Списание остатка — отдельное подтверждаемое учётное действие с нулевым поступлением денег, не биржевая продажа.

Перетаскивание Stop/Target меняет черновик. «Изменить защиту · предпросмотр» показывает старые и новые уровни, риск и покрытие. Только подтверждение сохраняет защиту. Монитор работает при запущенном процессе и свежих данных; сон/выключение компьютера прекращают наблюдение. Частичное покрытие явно отмечено.

## Проверки и ограничения

Добавлен GitHub Actions workflow, запускающий pytest на Windows и macOS с Python 3.12. Это автоматическая проверка тестового набора, но не замена ручной проверке UI и сетевого подключения на реальных устройствах. Исторический отчёт тестов — [TEST_REPORT_FINAL.md](TEST_REPORT_FINAL.md).

В исходной тестовой среде реальный Bybit REST дал HTTP 200 с HTML Site Unavailable вместо JSON; WS handshake отвергнут. Production UI показывает Connection Lost и блокирует торговые действия. Повторная сетевая проверка требуется на каждом устройстве.

Forecast отображается как UNAVAILABLE. Нет подключённой модели, проверенного Forecast Overlay, бэктеста или заявлений о прибыльности. Demo, Live, autonomous и вывод средств не включены.
